# Narra（創作チャットPWA）

iPhone の Safari でホーム画面に追加して使う、**自分専用**の創作チャットアプリです。ロールプレイと小説の執筆に使います。
画面の文言はすべて日本語です。

公開先：https://yoru-polaris.github.io/narra-pwa/

この文書は、人や AI がコードを読んでレビューするときの手引きです。

---

## 前提と制約

- **ビルドなし。** HTML / CSS / JavaScript（ES modules）をそのまま GitHub Pages で配信しています。npm も外部ライブラリもありません。
- **サーバーなし。** ブラウザから AI の API を直接呼びます。
  - Vertex AI（API キー方式。`x-goog-api-key` ヘッダー）
  - Gemini API（Google AI Studio）
  - OpenAI 互換 API（OpenRouter など）
  - ダミー AI（通信せず決まった文を返す。動作確認用）
- **データはすべて端末内。** IndexedDB と localStorage に保存し、JSON ファイルで書き出し・読み込みします。
- **API キーは端末内だけ。** 書き出しファイルにも、通信の記録にも入れません。
- **主な実行環境は iPhone の Safari（ホーム画面に追加した PWA）。** キーボード表示時の画面のずれ、古い iOS の正規表現の対応などに気を配っています（後述）。
- 利用者は1人です。不特定多数に配る想定はありません。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み。パネル（一覧・設定・この話の設定・下から出るシート・スマホ・編集画面）を最初から置き、`hidden` で出し入れする |
| `css/style.css` | 見た目。配色は `:root` と `[data-theme=…]` の CSS 変数。後ろに追記する形で育てたので、同じ要素への指定が複数あり、**後に書いたものが優先**される |
| `js/app.js` | 画面と機能のほぼすべて（状態管理・描画・会話の木・設定・書き出し/読み込み・ゴミ箱・要約・差し込み・検索・読むモードなど） |
| `js/api.js` | 各 API への送信と、SSE ストリームの読み取り。エラー文の日本語化。通信の記録 |
| `js/db.js` | IndexedDB の薄いラッパー。保存時に `savedAt` を付ける |
| `js/phone.js` | 「スマホをのぞく」。AI に JSON を作らせ、スマホ風の画面に組み立てる |
| `js/inserts.js` | 差し込みプロンプトの見本（初回だけ設定に入る） |
| `sw.js` | Service Worker。ネット優先・失敗時にキャッシュ（オフラインでも画面は開ける） |
| `manifest.json` / `icons/` | PWA の情報とアイコン |

`app.js` の中は `// ---------- ○○ ----------` の見出しで区切っています。

## 画面の作り

- ページ全体を固定し、メッセージ欄（`#messages`）だけがスクロールする「アプリ型」です。
- `window.visualViewport` で実際に見えている範囲を測り、CSS 変数 `--vh` `--vt` `--vb` に入れて、画面全体をそこに合わせます（iOS でキーボードが出たときに入力欄が隠れる・浮く問題への対策。`fitViewport()`）。
- 長い文章の欄（`textarea`）は、その場では編集させず、タップすると全画面の編集画面（`#editor`）を開きます（キーボード表示時に欄が細い帯になる問題への対策。`tapToEdit()` / `openEditor()`）。
- 描画は `render()` がメッセージ欄を毎回作り直す方式です。長い会話は直近 60 件だけ描きます（`PAGE`）。
- DOM は小さなヘルパー `h(tag, props, ...children)` で組み立てます。**`innerHTML` は使っていません**（AI の返事に HTML が混ざっても実行されないように）。

## データの持ち方

### IndexedDB（データベース名 `sousaku`、バージョン 2）

| ストア | キー | 中身 |
|---|---|---|
| `chats` | `id` | チャット |
| `messages` | `id`（索引 `chatId`） | メッセージ（会話の木の節） |
| `prompts` | `id` | プロンプト（システムプロンプト） |
| `chars` | `id` | カード（主人公・登場人物・世界設定・資料） |
| `kv` | `key` | `settings`（設定一式）、`bg`（全体の背景画像 Blob） |

`chats` `messages` `prompts` `chars` は、`db.put` / `db.putMany` で保存するたびに `savedAt`（保存日時）が付きます。読み込み時に「手元とファイルのどちらが新しいか」を比べるためです。

### 会話は木

- メッセージは `parentId` で親を指します。再生成・編集・分岐をしても、元のメッセージは消さずに兄弟として残ります。
- チャットの `leafId` が「今見ている枝の先」です。表示も、AI に送る履歴も、`leafId` から根までたどった一本道（`pathTo()`）です。
- 子の一覧は `childrenOf()` で、メッセージの追加・削除のたびに作り直す索引（`kidsIndex`）を使います。

### 主なフィールド

**チャット**：`title` `promptId` `heroId`（主人公カードの id／`'custom'`／`null`） `heroCustom`（この話だけの主人公） `charIds`（登場人物・世界設定・資料のカード） `note`（今回の話） `summary`（あらすじ：`text` と `uptoId`） `summaryOn` `peeks`（スマホをのぞいた記録） `pinned` `leafId` `deletedAt`（ゴミ箱） `createdAt` `updatedAt`

**メッセージ**：`chatId` `parentId` `role`（`user`／`assistant`） `text` `thought`（思考） `thoughtJa`（その訳） `files`（添付）／`filesRef`（添付を持つ別メッセージの id） `side`（番外） `label`（枝の名前） `collapsed` `usage`（トークン数） `model` `modelId` `notice` `loaded`（読み込んだ詳細） `deletedAt` `trashGroup`

**カード**：`type`（`hero`／`char`／`world`／`doc`） `name` `core` `detail` `keywords` `alwaysDetail` `greeting`（始まり方） `icon` `bg`（Blob）

### localStorage

- `sousaku:draft:<チャットid>`：入力欄の書きかけ
- `sousaku:netlog`：通信の記録（直近 80 件。時刻・用途・モデル・接続先・大きさ・結果だけ。本文とキーは入れない）

## AI に送る内容（`buildSystem()` と `generate()`）

システムプロンプトは次の順に組み立てます。

1. プロンプト
2. 世界設定（基本は毎回、詳細はキーワードが直近4件に出たとき）
3. 主人公
4. 登場人物（核は毎回、詳細は名前かキーワードが出たとき。`alwaysDetail` なら毎回）
5. 資料（毎回まるごと）
6. 今回の話
7. これまでのあらすじ（要約を使う場合）

そのあと `fillNames()` で `User` `{{user}}` `{{char}}` を名前に置き換えます。

会話の履歴は今の枝の全部です。ただし、番外（`side`）は送りません。要約済みの部分も送らず、あらすじに置き換えます。

## 主な仕組み

- **自動やり直し**：429・5xx・通信失敗で、返事が1文字も来ていなければ、待ち時間を延ばしながらやり直す。429 が続くと、接続先に設定した予備のモデルに回す。
- **Vertex のリージョン**：接続先にリージョン（`global` など）を指定できる。プロジェクト番号が空なら、一度短い形の URL で呼び、「モデルが見つからない」エラー文から番号を拾って指定のリージョンでやり直す（`vertexUrl()`）。
- **ゴミ箱**：削除は `deletedAt` を付けるだけ。30 日後に起動時に完全削除（`purgeTrash()`）。完全削除するメッセージの添付を他の枝が参照していれば、添付をそちらへ移す（`eraseMessages()`）。
- **書き出し・読み込み**：書き出しはチャット・メッセージ・プロンプト・カード・差し込み・設定（API キー以外）を1つの JSON に。巨大な文字列を作らないよう小分けにして `File` にする。読み込みは同じ id を `savedAt` で比べ、新しいほうを残す（`mergeInto()`）。
- **番外**：日記・掲示板などの出力。会話の木の中に `side: true` で置くが、AI に送る履歴・コピー・要約からは除く。
- **スマホをのぞく**：会話とは別に1回だけ送り、JSON（`responseMimeType: application/json`）で中身を作らせて描画する。JSON 指定に非対応なら指定なしでやり直す。

## 気をつけていること・既知の制約

- **iOS 16.3 以前の Safari は正規表現の後読み（`(?<!…)`）を読めない**ので使っていない。使うとアプリ全体が起動しなくなる。
- 入力欄の値は、入力中に少し待って自動保存し、画面を閉じる・アプリを裏に回すときにも保存する（iOS では入力欄から「離れた」扱いにならないまま閉じられることがあるため）。
- 全体の背景画像は `kv` の `bg` に Blob で保存。人物カードの `icon` `bg` も Blob。書き出し時に data URL に変換する。
- キャッシュ書き込みの割増料金は、API から量が返らないため換算トークンに含めていない。
- テストはリポジトリに入れていない（開発中に Playwright で iPhone サイズの画面を動かして確認している）。

## 確認のしかた

```bash
python3 -m http.server 8765
```

`http://localhost:8765/` を開き、歯車 →「接続先」の種類を「ダミーAI」にすると、API キーなしで画面の動きを確かめられます。
